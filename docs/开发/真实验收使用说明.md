# 真实验收使用说明

本工具显式调用既定的 glm-5.3-flash 和 embedding-3，仅用于自编虚构条款与案件的验收。生产启动和常规测试不会调用本工具。

## 执行边界

2026-10-27 用户批准的累计上限为 270 次模型、110 次 Embedding 请求。所有运行默认共用 `data/evaluation-provider-budget.json`，也可通过 `--budget-ledger` 显式指定同一文件；更换输出目录不会重置额度。第一次建立共享账本时会读取既有历史运行，当前历史预占为模型 2 次、Embedding 0 次。工具在请求发出前持久预占，超限、供应商错误、繁忙、鉴权错误或模糊请求会停止后续调用；没有自动重试。

共享账本、源码指纹、验收 schema 和阶段状态共同约束恢复。源码、账本路径或额度上限变化，账本缺失，存在未决阶段，或账本已 stopped / reserved / ambiguous 时，`--resume` 都会拒绝继续，不能用恢复绕过安全停止。

若操作人已通过网络和供应商侧记录核对唯一 `ambiguous` 调用，可用 `scripts/reconcile_evaluation_budget.py` 指定准确 callId、runId、kind 和操作人，将其确认成 `consumed`。该操作不会退还额度、删除历史或恢复原 run；原 run 仍有 `inProgress` 时必须保留为失败证据，后续使用新输出目录重新开始 capability。

开发库与验收库分离。真实验收只使用新建的 `casepilot_eval_<UUID>` 及其 checkpoint schema；不删除开发任务、旧报告或知识发布。验收 schema 和报告保留供溯源，不把固定向量或模拟响应写入其中。

## 运行

先完成数据库、契约与前端回归，再从仓库根目录执行：

```powershell
.venv\Scripts\python.exe scripts\evaluate_v1.py --live --stop-after capability --model-limit 270 --embedding-limit 110 --output docs/验收/本轮真实验收
```

首次运行的输出目录必须不存在，避免覆盖以前结果。`--stop-after` 默认为 `capability`，最小能力门禁通过后不会自动继续消耗索引和报告额度。后续使用完全相同的输出目录、源码和账本分批恢复：

```powershell
.venv\Scripts\python.exe scripts\evaluate_v1.py --live --resume --stop-after retrieval --model-limit 270 --embedding-limit 110 --output docs/验收/本轮真实验收
.venv\Scripts\python.exe scripts\evaluate_v1.py --live --resume --stop-after round-one --model-limit 270 --embedding-limit 110 --output docs/验收/本轮真实验收
```

`round-one` 完成十个样本的第一轮后，以 `ROUND_ONE_SEMANTIC_REVIEW_REQUIRED` 安全暂停；此时共享账本保持 active，不执行第二、三轮或替换发布。填写并签署 `manual-review.json` 后，再执行：

```powershell
.venv\Scripts\python.exe scripts\evaluate_v1.py --live --resume --stop-after automated --model-limit 270 --embedding-limit 110 --output docs/验收/本轮真实验收 --keep-server
```

也可通过已安装开发依赖的 `uv run --package casepilot-api --extra dev python` 执行。`--keep-server` 只在后两轮、替换发布等自动门禁通过后保留本地真实 API，供浏览器验收；它仍受同一共享账本约束。各阶段正常结束不会冻结共享账本。浏览器操作结束后调用 `/evaluation/freeze` 冻结供应商请求并停止该验收实例，不作为无限额度开发服务。

## 固定顺序

1. 最小真实工具调用、JSON 对象响应和 1024 维 Embedding；任一步失败不进入后续门禁。
2. 导入自编 12 页条款，以及错误险种和旧版本干扰文档；向量由真实服务返回。
3. 批量向量化冻结的 24 道问题，实际执行 pgvector 查询；有答案题 Hit@4 至少 90%，元数据串库为零。无答案题记录返回片段，不把“有最近邻”算作有依据。
4. 先运行 10 个报告问题各一次，真实执行任务、必要审核和三节生成；第一轮必须完成人工语义签署，才允许恢复并执行第二、三轮。检查规则保留、固定版本、证据不足、提示注入、实际引用支持和预算。失败立即停止该批次，不修改数据标签迎合输出。
5. 发布替换文档，保留原 generation；使用原会话及新会话完成真实浏览器追问、引用和版本检查。
6. 对实际报告与保存原文逐条审查语义支持，填写 T01–T26 证据。自动结构检查不代替此步骤，工具默认输出 `manual_review_required`，不会自动声明完整验收通过。

## 数据与产物

- `tests/evaluation/corpus.json`：自编英文演示条款，每页一条，含不应被执行的引用文本；不是现实保险产品或真实保单。
- `tests/evaluation/retrieval.json`：24 道中文改写题，12 有答案、6 元数据干扰、6 无答案；中文问题检索英文自编条款的结果单独记录，不外推到全部中文保险语料。
- `tests/evaluation/reports.json`：10 个虚构案件／问题样本，每个三次运行，标注规则和证据不足要求。评测标签不进入业务提示词。
- `source-manifest.json`、`run-state.json`：冻结代码、依赖、配置和数据哈希，以及可恢复阶段、schema 和共享账本绑定。
- `results.json`、`budget-summary.json`：门禁状态、任务标识和本次运行看到的累计预算摘要；完整调用记录只保存在共享账本中。
- `capabilities.json`、`retrieval-results.json`、`tasks/`：最小能力门禁、完整检索片段、实际报告与分析／调用审计。
- `manual-review.json`、`browser/checklist.json`、`recovery/results.json`：三十份报告人工语义审查、真实浏览器矩阵和供应商在途恢复证据。

只有真实请求成功且人工语义审查完成，才能推进相应验收项。前置失败时，其余项目记为未执行或阻塞，不用测试适配器补齐“成功结果”。
