# 项目结构与维护规范

本项目采用按应用划分的单仓库结构。pnpm 管理前端与契约包，uv 管理 Python API；两个锁文件分别约束各自的依赖，不合并、不手工修改。

## 目录职责

| 路径 | 职责与约定 |
| --- | --- |
| `apps/api/src/casepilot/` | 可安装的 Python 包；`__main__.py` 正式启动，`main.py` 组装应用，`bootstrap.py` 管理资源与 worker，`config.py` 统一加载本地环境 |
| `apps/api/src/casepilot/api/` | 案件、分析、知识库、readiness 路由，SSE 封装与 HTTP 错误映射 |
| `apps/api/src/casepilot/cases/` | 虚构案件 seeds、隔离快照读取与确定性规则 |
| `apps/api/src/casepilot/workflow/` | V0 state/nodes/graph；G3 agent_state/agent_nodes/agent_graph、实际 tools 和版本化 prompts。G3 尚未替代正式入口 |
| `apps/api/src/casepilot/analyses/` | 应用用例、任务投影、生命周期、模板报告、命令执行及重启对账；G3 agent/evidence/ledger 提供固定上下文与有界分析，不依赖 FastAPI |
| `apps/api/src/casepilot/model/` | 不可变配置、脱敏错误、供应商通信、Embedding、显式探测；`__main__.py` 保留原探测命令 |
| `apps/api/src/casepilot/persistence/` | 连接池与 checkpoint 资源、单 worker 锁、分析事务、知识库迁移、数据库只读检查 |
| `apps/api/src/casepilot/schemas/` | Pydantic 传输模型；可独立导出，不导入应用或数据库运行时 |
| `apps/api/src/casepilot/knowledge/` | PDF 解析、处理配置、导入服务、事务仓储及发布/检索；`demo.py` 明确隔离 V0 关键词检索 |
| `apps/web/src/pages/` | 页面容器，组合工作台或知识库功能 |
| `apps/web/src/components/` | 展示与用户输入组件 |
| `apps/web/src/composables/` | 页面异步流程、订阅与生命周期 |
| `apps/web/src/api/` | HTTP 调用与传输校验 |
| `apps/web/src/domain/` | 展示映射、事件归并与请求作用域纯函数 |
| `packages/contracts/src/analysis.ts` | 仍在使用的 V0 案件分析类型与校验入口 |
| `packages/contracts/src/knowledge.ts` | 当前知识库类型与校验入口 |
| `packages/contracts/src/transport.ts` | Ajv 通用校验，不重复手写 DTO |
| `packages/contracts/schema/`、`src/generated/` | Pydantic 导出的 JSON Schema 与生成的 TypeScript；提交到版本库 |
| `packages/contracts/tests/` | 契约包自己的响应校验测试 |
| `tests/api/` | 后端单元、HTTP/SSE、数据库和独立进程恢复测试及夹具 |
| `tests/web/unit/` | 前端纯函数测试 |
| `tests/web/integration/` | Vue composable 生命周期和异步隔离测试；不代表浏览器端到端验收 |
| `scripts/` | 仓库级启动、检查和测试入口 |
| `infra/` | 基础设施初始化；根 `compose.yaml` 为开发数据库入口 |
| `docs/使用/`、`docs/设计/`、`docs/开发/` | 按读者目的组织说明，文件使用中文名 |
| `docs/资源/` | 当前文档引用的图片；不用截图代替测试结果 |

内部职责与依赖约束见 [内部架构检查与整理](内部架构检查与整理.md)。采用适合当前 FastAPI/LangGraph 应用的模块结构；Tools 和提示词已随 G3 组件落地，不为尚未实现的多轮会话预建空包。

## 命名与配置

- 说明文档使用中文文件名，源码、导入路径、包名和自动化脚本使用语言惯用命名。
- `package.json`、`pyproject.toml`、锁文件、`.env.example`、`.gitignore`、`compose.yaml` 等保留工具要求的名称。
- 根 `项目说明.md` 是安装运行入口，`docs/文档索引.md` 是文档导航。新增文档应加入索引，移动文档应同步全部相对链接。
- `.env`、`.venv/`、`.tools/`、`node_modules/`、`dist/` 和缓存是本地环境或产物，由 `.gitignore` 排除。环境、下载工具和用户配置不作为废弃源码删除。
- 本次保留 uv、pnpm 锁文件与 Python 版本声明；不通过升级依赖完成目录整理。

## 契约更新

1. 修改 API 的 Pydantic 传输模型：`schemas/analysis.py` 或 `schemas/knowledge.py`。
2. 如新增导出模型，同步 `export_schema.py`。
3. 执行 `pnpm contracts:generate`，提交 JSON Schema 和 TypeScript 生成结果。
4. 执行 `pnpm contracts:check`、`pnpm test:web`、`pnpm build` 和相关后端测试。

不在前端另行手写尚未实现的请求 DTO。规划协议保存在设计文档中，随对应 API 落地再建立可执行契约。

## 删除与验证

删除文件前检查入口、import、脚本、生成过程和文档引用。文件名含 `legacy`、文件未被直接 import、文件是生成产物，均不足以单独证明可删除。

删除或移动后运行对应测试和构建；涉及 pytest 发现路径、进程工作目录或测试辅助进程时，同时核对配置、启动脚本和子进程路径。常规测试不请求真实模型，数据库验收显式启用且只清理测试 schema。
