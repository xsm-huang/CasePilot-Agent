# 测试说明

后端测试位于 `tests/api/`。HTTP 用例启动真正的 uvicorn 子进程，使用 TCP 连接验证暂停期间 SSE 已返回数据，再提交审核并观察后续事件；不是会缓冲响应的 ASGITransport 测试。

从仓库根目录运行（安装后端 dev 依赖后）：

```bash
uv run --package casepilot-api --extra dev python scripts/test.py -q
uv run --package casepilot-api --extra dev python scripts/test.py --database -q
pnpm test:web
pnpm contracts:check
pnpm build
```

`pnpm test` 汇总后端常规测试、契约测试与前端测试，需要 uv 在 PATH 中。`pnpm test:api:database` 显式启用实际数据库。直接运行现有环境时，Windows 可用 `.venv/Scripts/python.exe scripts/test.py -q`。

## 目录与发现方式

| 目录 | 测试层次 | 运行方式 |
| --- | --- | --- |
| `tests/api/` | Python 规则、适配器、PDF、HTTP/SSE、数据库与恢复 | pytest 通过根 `pyproject.toml` 的 testpaths 自动发现 |
| `tests/web/unit/` | 前端事件归并、请求作用域纯函数 | `pnpm test:web` |
| `tests/web/integration/` | Vue mount/unmount、迟到请求、重试与版本冲突 | `pnpm test:web`；使用自定义 renderer，不是浏览器 E2E |
| `packages/contracts/tests/` | Python 生成契约的 Ajv 响应校验 | `pnpm --filter @casepilot/contracts test`，先构建该包 |

API 夹具与辅助进程留在 `tests/api/`，不进入生产包。测试自有临时端口与子进程，不停止现有服务；普通测试不发送真实模型或 Embedding 请求。

`test_architecture.py` 额外约束业务/工作流不得依赖 HTTP 与应用装配层、图构造不得执行数据库或供应商副作用、Schema 不得依赖运行时，并验证两个应用工厂实例的任务状态互相隔离。数据库组件测试检查应用错误码，HTTP 测试继续检查原状态码与响应形状，两层契约分别验证。

## 证据分类

| 分类 | 覆盖 | 边界 |
| --- | --- | --- |
| 确定性迁移 | 两案固定规则、关键词条款、HTTP 输入错误、通过/驳回、任务隔离、SSE 实时读取与重放 | 使用 V0 模板报告；不调用模型，不证明语义 RAG 或真实章节生成 |
| 数据库与进程 | PostgreSQL 独立测试 schema、审核恢复、事件编号、G2 发布/版本隔离与中断恢复 | 使用固定演示材料与 Embedding 替身；不证明真实语义质量和全部模型调用崩溃窗口 |
| 真实联合服务 | 不在本测试套件中执行 | 必须单独执行并记录实际模型/Embedding/数据库/浏览器结果与预算 |

数据库验收由 `CASEPILOT_TEST_DATABASE_URL` 显式启用；未设置时应报告跳过，不能写为数据库测试通过。测试只创建和删除带随机 UUID 的 `casepilot_test_` schema，不清理用户数据库表、容器或数据卷。

## G2 知识库新增证据

- `test_pdf_ingestion.py`：实际 LangChain PyPDFLoader / splitter，真实文字多页、跨页条款按真实页分别溯源、空页不移位、100/101 页边界、空/扫描/加密/损坏 PDF。夹具由 `pdf_fixtures.py` 自编，扫描夹具包含真正的图像 XObject。
- `test_embedding_adapter.py`：HTTPX MockTransport 验证批量请求、index 排序、维度/数量/有限数/float32 溢出与归零、布尔拒绝、1305 结构化脱敏信息。它只证明适配器契约，不证明供应商已返回真实向量。
- `test_knowledge_database.py`：实际 PostgreSQL `vector(1024)` 写入和余弦算子查询；险种/业务版本/generation/profile 隔离；构建中查询仍读旧发布；第 2 批失败；重复导入和请求幂等；并发 CAS 仅一发布；retry 不擅自基于新版本重试；版本化 schema 迁移和 publication 跨范围 FK。
- `test_knowledge_recovery.py`：独立组件进程在真实持久阶段写入后设置测试屏障，分别强杀 parsing/chunking/embedding；随后启动正式 API 验证 `INDEXING_INTERRUPTED`、旧发布不变，再显式 retry。屏障仅存在于测试进程，生产 API 没有测试后门；这不等于验证外部 Embedding 请求在途时的恢复。
- `test_knowledge_http.py`：正式 API 子进程验证 413/415/422、multipart、完整 Generation DTO、异步解析失败、缺 Key 明确失败及幂等 retry；另以组件替身验证数据库/未知异常 503/500 脱敏。子进程凭据显式置空，不执行付费请求。

以上数据库测试全部只用注入的固定向量替身；不得据此声称真实 Embedding、真实语义质量或 Hit@4 达标。

## 对照 V1 验收方案

对应 [验收方案](../设计/验收方案.md) 中的 T01–T26。

迁移基线直接覆盖 T21，部分覆盖 T03、T06（关键词元数据隔离）、T16、T17、T18（后端任务隔离）、T22 和 T23（重复审核冲突）。完整 V1 仍缺：

- T01/T02：真实模型、结构化输出、模型触发工具调用。
- T03：完整的缺失/非法日期、所有材料与案件来源冲突矩阵。
- T04：已覆盖本轮支持的文字 PDF 解析及明确拒绝边界；不支持 OCR。
- T05–T07：已覆盖真实 pgvector 数据约束/查询、元数据隔离、原子发布与中断恢复；实际供应商 Embedding 联合链路仍未验证。
- T08–T10：旧 generation 可检索已测；分析会话固定来源快照、语义题集/Hit@4 及模型无依据策略尚未完成。
- T11–T14：跨恢复预算、结构修复、引用支持结论、三次真实生成的分节增量。
- T15/T18：工具执行标识和浏览器快切的延迟请求隔离。
- T19/T20：持久多轮会话与同会话串行约束。
- T23/T24：请求幂等 Key、interruptKey、命令/投影/模型调用各崩溃窗口。
- T25/T26：文档引用定位、越权引用、真实服务故障、提示注入和 HTML 输出边界。

上述是剩余工作清单，不是已通过的测试结果。实际结果以执行输出和 [实施状态](实施状态.md) 为准。
