# 项目结构整理记录

日期：2026-10-23。范围：当前工作区的结构、废弃文件与说明文档整理；工作区原有 Python 迁移和知识库改动作为基线保留。

## 步骤、意图与原因

| 步骤 | 操作与意图 | 判断原因 |
| --- | --- | --- |
| 1. 建立基线 | 检查 Git 状态、文件树、包配置、脚本、导入和文档；先运行现有测试 | 项目已有大量未提交改动，需要区分既有迁移与本次整理，避免误删有效实现 |
| 2. 保留主体布局 | 继续使用 `apps`、`packages`、`infra`、`scripts`、`tests`、`docs` | 应用、共享包、基础设施和测试已经分离，无需为形式更换可用目录 |
| 3. 整理测试 | `tests/python` → `tests/api`；`tests/setup` → `tests/web/unit`；知识库测试移入 `tests/web/integration` | 按应用和测试层次命名；原 setup 并非环境准备测试，知识库用例并非真实浏览器验收 |
| 4. 同步运行入口 | 修改 pytest testpaths、前端相对导入、辅助进程路径和测试脚本；`pnpm test` 汇总 API 与前端 | 移动目录后必须保证发现、导入、子进程和统一命令仍然有效；pytest 路径只在配置声明一次 |
| 5. 清理契约 | `legacy.ts` → `analysis.ts`；删除未使用的 `commands.ts`、`status.ts`、`system.ts` 及仅供它们使用的 zod 声明 | 分析契约仍在服务生产页面，不能因 legacy 名称删除；另外三个文件只有定义与入口导出，业务和测试均无使用，且包含尚未实现功能的预定义 |
| 6. 统一包测试目录 | `packages/contracts/test` → `packages/contracts/tests` | 与仓库的复数 tests 命名保持一致，包级测试留在所属包内 |
| 7. 中文文档分类 | 根入口改为 `项目说明.md`，建立文档索引与使用/设计/开发/资源分类 | 中文名称便于定位；目录按读者目的组织，工具配置保留约定英文名 |
| 8. 合并重复说明 | 将原型接口和演示并入功能流程；迁移成果与约束并入实施状态；测试说明移入开发文档 | 同一能力不在多份阶段说明中反复维护，避免读者把旧状态当成当前事实 |
| 9. 修正过期内容 | 更新 PostgreSQL 重启恢复、G2 知识库现状及模型验证边界；保留 V1 设计与 T01–T26 标准 | 旧文档中的纯内存限制和旧 Node.js 探测成功不能代表当前 Python 实现 |
| 10. 清理残留目录与产物 | 删除已空的旧后端目录及已过期的构建输出；重建产物由构建验证生成 | 源码移动/删除后，空目录和旧 JS/d.ts 不应造成仍有旧实现的错觉 |
| 11. 回归验证 | 运行 API、数据库恢复、契约、前端测试、构建、Ruff 与链接检查 | 目录看起来整齐不足以证明可用，必须确认实际入口与行为保持 |
