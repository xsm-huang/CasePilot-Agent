# 模型适配与切换说明

## 当前配置

2026-10-27 经用户确认，将聊天模型切换为 `glm-5.3-flash`。Embedding 继续使用 `embedding-3`、1024 维，接口地址和密钥来源不变。

切换前单次基础聊天实测返回 HTTP 200、正文 `OK`，耗时 3.6 秒，总计 165 Token，其中思考 Token 147。该结果只证明基础聊天可用，不代表工具调用、结构化输出或完整业务质量验收通过。此前旧模型的验收记录保留原样。

## 适配边界

- `apps/api/src/casepilot/model/profiles.py`：集中定义允许使用的模型、默认模型、思考开关、思考回传策略和各用途输出上限。GLM-5.3-Flash 的业务请求为 4096 Token、能力探测为 2048 Token、手动最小测试为 1024 Token。思考也消耗输出额度；截断仍按显式错误处理，不自动重试。
- `model/config.py`：读取配置并通过模型配置表校验。`.env` 和 `.env.example` 的 `CHAT_MODEL` 指定当前模型；本地检查脚本共用同一配置表。
- `model/chat.py`：统一发送请求、解析响应及重建内部助手消息。工作流使用统一的 `assistant_message`，不直接判断模型名称或拼装思考字段。
- `model/probe.py` 与 `scripts/test_chat.py`：复用相同模型配置，避免诊断脚本与业务参数不一致。

新模型强制开启思考；工具调用后按供应商要求回传完整、未修改的 `reasoning_content`。该内容只保存在内部调用账本和工作流 checkpoint，用于工具续调、结构修复及恢复；公开任务、事件、报告与会话消息不包含该内容。持久存储中因此可能包含内部思考数据，应沿用业务数据的访问控制。

官方依据：[GLM-5.3-Flash 参数](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)、[思考与工具调用消息要求](https://docs.bigmodel.cn/cn/guide/capabilities/thinking-mode)。

## 后续切换步骤

1. 在模型配置表中增加已确认兼容的模型配置，再修改默认模型、`.env` 与 `.env.example`。参数差异集中放在模型层；若供应商响应格式不同，在模型层适配为现有统一结果。
2. 运行配置、聊天适配、工具循环、恢复和公开数据边界的离线测试；新模型再单独完成真实能力及质量验收，不能沿用旧模型成绩。
3. 重启 API 后新建会话。会话和任务固定模型上下文，已有旧模型任务与会话不会自动迁移，也不修改历史报告。

本次未引入数据库结构变更，未改变单任务最多 8 次模型调用、3 次检索和 1 次逻辑结构修复的限制。输出上限增加可能提高单次 Token 消耗，真实质量验收仍需单独记录实际用量。
