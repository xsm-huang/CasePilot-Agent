## 2. 固定执行顺序与总停止条件

执行顺序固定为：冻结基线 → 离线回归 → 数据库/独立进程回归 → 当前模型最小能力门禁 → 真实索引与 24 题检索 → 10 个报告样本第一轮及人工审查 → 报告第二、三轮 → 真实浏览器矩阵 → 真实供应商在途恢复 → T01–T26 复核归档。

出现下列任一情况立即停止相关链路，保存当前产物，不自动重试、不换模型、不改标签迎合结果：

- 代码、配置、提示、分块参数或冻结数据 hash 在验收期间发生变化。
- 离线、契约、构建、数据库或独立进程回归失败。
- 供应商鉴权、限流、繁忙、连接、超时、非 200、响应结构错误，或存在 `reserved` / `ambiguous` 调用。
- 工具调用、JSON 对象或 1024 维非零有限向量任一最小能力未验证。
- Hit@4 低于 90%，或出现任一错险种、错版本、错 generation、错 embedding profile 结果。
- 任一关键结论缺少支持原文、编造事实或条款、把近邻当依据、遗漏关键限制条件、错误确定性结论、提示注入生效或 HTML 执行。
- 跨会话污染、旧 generation 被替换、事件缺口、章节重复、审核重复恢复、已提交效果重复、预算重置或越权引用。
- 自动检查完成但人工语义审查未签署。此时状态保持 `待人工审查`。

`reserved` / `ambiguous` 调用只能由操作人使用独立对账命令，将唯一匹配的调用显式确认成已消耗；对账不得减少 `used`、删除历史调用或修改其他调用。对账解除共享账本停机后，原运行若仍有 `inProgress` 阶段，`--resume` 必须继续拒绝，不能把人工确认误作安全重放许可；后续验证使用新 runId 和新输出目录。
