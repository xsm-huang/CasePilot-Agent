# CasePilot Agent 功能拆解与 MVP 边界

目标不是一次覆盖全部简历能力，而是逐阶段产出可演示、可测试、边界清晰的结果。当前已实现 V0 流程原型；要支撑所给简历中的完整表述，还需完成 V1/V2。

## 1. 完整产品能力地图

| 模块 | 核心功能 | MVP | 后续迭代 |
| --- | --- | --- | --- |
| 案件中心 | 案件列表、详情、材料目录、历史任务 | 预置案件列表与材料摘要 | 上传、批量导入、权限与检索 |
| Agent 编排 | 多节点执行、Tools、条件分支、失败重试 | 查询、校验、检索、审核、报告节点 | 并行子图、重试策略、任务队列 |
| 确定性规则 | 缺件、字段一致性、日期/金额规则 | 缺少发票、事故早于生效、跨材料日期冲突 | 金额核验、可配置规则 DSL、版本和命中统计 |
| 条款 RAG | 解析、分块、向量索引、元数据过滤、引用 | 内存关键词检索 + 险种/版本过滤 + 条款 ID/原文 | LangChain、pgvector、Embedding、混合检索、重排 |
| AI 分析 | 疑点归纳、补充检索、结论与报告 | 基于规则和检索结果生成模板报告 | 接入模型、工具协议、提示词版本、质量评测 |
| 人工审核 | interrupt、审批、驳回、补充意见、恢复 | 有疑点则暂停；通过继续/驳回结束 | 多级审核、改派、超时提醒 |
| 实时交互 | 增量输出、工具卡片、时间线、状态同步 | SSE 事件流、时间线、重连与内存游标重放 | token 流、跨进程事件补偿、多端状态推送 |
| 任务治理 | 历史记录、状态筛选、审计、可观测性 | 内存任务状态与事件记录 | PostgreSQL 持久化、指标、日志追踪 |

## 2. MVP 用户故事

核赔人员打开工作台，选择一个车险理赔案件并点击“开始分析”。系统实时展示案件查询、材料校验和条款检索的执行过程。当规则发现缺件和日期冲突时，Agent 自动进入人工审核。核赔人员填写意见并通过，Agent 从中断点恢复，输出包含事实摘要、疑点、建议和条款依据的报告。

## 3. 验收标准

- 启动分析后，页面能按顺序收到至少 4 类 SSE 事件：节点状态、工具调用、审核请求、报告完成。
- 示例案件稳定命中 2 个疑点，且不会依赖随机模型输出。
- 条款检索必须按 `productCode`、`version` 过滤，报告中的引用能展示条款 ID 和原文。
- 审核前不得生成最终报告；审核通过后同一任务 ID 可以继续执行。
- 页面刷新后可通过任务详情接口恢复当前状态和既有时间线。
- 工作流规则与条款检索具备单元测试。

## 4. 暂不纳入 MVP

- OCR/PDF/DOCX 解析、真实对象存储与上传。
- 真实大模型、Embedding 和 pgvector 部署。
- 登录、组织/角色权限、生产级数据脱敏。
- 分布式任务队列、多实例 SSE、跨进程事件游标补偿。
- 规则配置后台、提示词评测平台与成本统计。

## 5. 演进路径

1. 用 PostgreSQL + pgvector 替换内存条款库，保留 `ClauseRepository` 接口。
2. 在规则结果之后加入 LLM 疑点分析节点，并用结构化输出约束结论。
3. 用 LangGraph checkpointer + PostgreSQL 持久化工作流状态，支持进程重启恢复。
4. 引入 BullMQ 运行长任务，以 Redis Streams 或持久事件表增强 SSE 重连。
5. 加入文档解析管线、检索评测集和报告事实一致性测试。

## 6. 对齐简历的实施阶段

| 阶段 | 必须交付的能力 | 完成标志 |
| --- | --- | --- |
| V0：流程验证（当前） | 预置案件、多节点图、规则分支、内存检索、审核恢复、SSE、历史任务 | 两个案件可走通；规则/流程测试、HTTP/SSE 冒烟检查通过 |
| V1：真实 AI + RAG | 一种格式的条款解析、分块、Embedding、pgvector、险种/版本过滤、LLM 结构化分析、真实 Tools | 上传条款后可检索；回答包含真实文档页码/片段；模型结论能回溯案件字段和条款 |
| V2：工作台补全 | 多轮对话、案件会话隔离、按疑点补充检索、持久 checkpoint、任务中断/恢复、文档材料入库 | 重启后可继续待审核任务；切换会话无串流；一次对话可触发补充检索 |
| V3：工程完善 | 失败重试/取消、评测集、权限、日志、性能与成本观测 | 可复现失败场景，有实际测试数据支持工程性描述 |

V1 的检索评测集至少包括：正确版本命中、旧版本排除、无相关条款、同名条款不同险种，以及正文和标题词不重合的语义检索。报告评测关注事实一致性、引用正确率和无依据结论，而不是仅观察模型是否生成了文本。

## 7. 本版业务约定

- 只演示车损理赔，不扩展到医疗、寿险等其他场景。
- 材料以预先提取的结构化字段表示，页面文件名不代表存在可下载的 PDF。
- 规则事实由程序确定；审核决定是否继续分析，当前不修改事实、不执行赔付。
- 任何疑点都进入审核；未来再按严重程度和规则配置调整分支。
- 当前报告一次性生成，流式粒度为工作流事件；逐 token/逐段输出留给模型接入阶段。
- 历史任务与状态仅在当前 API 进程存活期间有效。
