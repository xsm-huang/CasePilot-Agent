# 已结案车险赔案审查agent系统需求

日期：2026-10-27  
文档状态：需求说明，供后续实现与验收使用，不代表功能已经交付。

## 1. 产品定位与目标

系统面向车险理赔质检人员，对已结案赔案开展事后质量审查。

系统帮助审查人员整理事故和案件事实，核对材料，检索适用保险条款，检查信息冲突、处理依据不足和金额差异，并将发现与证据一起展示，由人工逐条核实，形成可追溯的审查报告。

系统的交付目标是：让审查人员能够说明“审查了哪些资料和项目、发现了什么、依据在哪里、人工如何认定、哪些事项尚未查清”。

审查应同时关注多赔、重复赔付、少赔、漏处理及作业记录缺陷。不能将降低赔款作为审查是否有效的判断标准。

## 2. 首期业务范围

### 2.1 适用对象

- 输入对象为已结案车险赔案及其关联档案，记录结案类型、结案时间、核赔结果和支付状态。
- 首期演示以普通车辆碰撞、车辆部分损失的已赔付结案案件为主，使用虚构且符合业务关系的数据。
- 拒赔、零赔付、全损、盗抢、追偿和诉讼等案件可记录基本情况，但未具备相应审查规则时，必须提示范围限制，不得展示为已完成相应专业审查。
- 一次事故可关联多个赔案；每次审查明确指定目标赔案和关联赔案资料，不能默认所有关联赔案档案均已取得。

### 2.2 AI 审查范围

本文件中的“车损部分”指车辆财产损失，包括本车车辆损失和第三方车辆损失，不仅指商业车损险。

系统须保留真实的保险关系：一辆车可关联交强险保单和商业险保单；商业险保单中列明实际承保的车损险、商业三者险等险种。各损失项目分别关联适用保单、险种和条款，不能将整案金额统一归入某一个险种。

首期自动审查以档案一致性、证据支持和可明确计算的金额核对为主。对于维修必要性、维修价格合理性等无法依据现有资料和规则确认的事项，输出待专业核实事项，不宣称已完成专业定损。

### 2.3 人伤与其他范围外事项

- 系统识别人伤标记，以及材料中出现的伤者、诊疗、医疗费用等线索，展示识别依据。
- 人伤状态包含“未发现人伤线索、有人伤、信息不足、信息冲突”，不能因没有填写人伤字段而自动认定无人伤。
- 发现人伤后，提示需要专业复核，并记录转交信息；车损审查继续执行。
- 对本车人员、第三方人员等已知身份分别记录；身份不明时保留不确定性，不能统一当作第三者。
- 人伤费用、伤残、医疗合理性和人伤赔款计算不在首期 AI 结论范围内。
- 若人伤材料涉及事故时间、责任等车损共用事实，保留其对车损判断的影响；关键事实未确定时，相应车损项目标为待核实。
- 人伤存在或信息不明确时，报告不能使用“全案无问题”等超出范围的结论。

### 2.4 与原理赔系统的边界

原赔案的报案、查勘、定损、核赔、支付和结案记录是审查输入。审查任务、人工意见和报告另行保存。

系统不直接改变原赔案结论，不执行实际支付、补赔、退款、追偿或重新开案。确认问题后，可记录后续建议、责任人员及办理去向。是否采取具体纠正措施，由有权限的业务人员按相应程序办理。

首期不要求建设报案受理、查勘调度、实时定损、银行支付或客户补件通知系统。

## 3. 使用人员与职责

| 人员               | 在本系统中的职责                                                     |
| ------------------ | -------------------------------------------------------------------- |
| 案件审查人员       | 查询案件、确认审查范围、启动审查、查证、逐条复核、补充发现、生成报告 |
| 条款与档案维护人员 | 维护条款资料，导入案件文件，核对文件归属和版本                       |
| 专业复核人员       | 接收需专业判断的事项；专业意见可由授权人员录入并关联依据             |

以上是业务职责，不要求首期同时建设复杂组织架构和多级审批系统。涉及人员操作的记录必须能够识别实际操作人，不能将 AI 作为人工确认人。

## 4. 业务对象与资料关系

| 对象           | 主要内容和关系                                                                   |
| -------------- | -------------------------------------------------------------------------------- |
| 事故           | 事故编号、时间、地点、经过、参与方、车辆、人员、责任认定和人伤情况               |
| 赔案           | 赔案号、关联报案号和事故、处理机构、结案类型和时间、原处理记录                   |
| 保单与批单     | 保单号、保险公司、车辆、投保人和被保险人、保险期间、承保项目、特别约定及适用批改 |
| 承保险种       | 隶属具体保单，记录险种、保险金额或责任限额、免赔约定和适用条款                   |
| 损失项目       | 损失所属车辆或人员、损失类型、申请金额、核定金额及证据；人伤项目保留范围标记     |
| 理算与核赔记录 | 关联赔案、损失项目、保单和险种，保存计算组成、调整原因、原意见和审批结果         |
| 支付记录       | 关联赔案及相应审批结果，记录收款对象、金额、成功或失败、退款及冲销等状态         |
| 案件材料       | 文件编号、类型、来源、所属案件、关联对象、版本和原文位置                         |
| 审查任务       | 审查对象、范围、输入版本、执行节点、发现、人工复核进度和报告版本                 |
| 审查发现       | 发现来源、问题描述、证据、判断依据、不确定性和人工复核记录                       |

同一份有效证据可以被多个有关联的检查使用，不要求为了不同险种重复上传。同一项损失在不同记录中出现，并不自动代表重复赔付，必须核实记录关系及状态。

## 5. 业务操作主流程

1. 审查人员通过赔案号等条件查找已结案赔案。
2. 打开案件详情，查看事故、保单、损失、原处理结果和材料目录。
3. 确认本次审查覆盖的赔案、车辆损失、条款及资料版本；查看缺失资料和范围限制。
4. 点击“启动审查”，系统创建独立审查任务并保存输入快照。
5. 系统整理事实、核验保单、核对材料、检索条款、核对金额并汇总发现，页面展示实际执行进度。
6. 系统输出待人工复核的发现，同时展示人伤等需专业复核的事项。
7. 审查人员逐条查看证据，选择确认问题、排除疑点、待补充核实或转专业复核，填写意见并保存。
8. 审查人员可补充 AI 未发现的问题，并记录依据。
9. 系统根据已完成检查和人工处理结果生成报告；尚有未决事项时形成明确标注的阶段报告。
10. 车损范围内的检查及复核满足完成条件后，生成车损最终审查报告，保留范围外转交事项及其状态。

原赔案保持已结案状态，审查过程不改变原赔案状态。

## 6. 功能需求

### 6.1 案件查询

- 支持按赔案号、报案号、车牌号查询。
- 支持按结案时间、人伤情况、审查进度筛选。
- 列表至少展示赔案号、车牌、出险和结案时间、原核赔或支付金额、人伤标记、最近审查状态。
- 各金额列须明确含义，不能用一个未说明口径的“案件金额”替代申请、核赔和支付金额。
- 无结果、加载失败和尚未导入数据应有明确提示，不能混为同一状态。

### 6.2 案件详情与材料查看

- 展示第 4 节的案件资料关系，明确本车和第三方，分别显示交强险和商业险信息。
- 保单中的每个实际承保险种单独展示；未投保、未取得保单和无法识别承保情况分别表示。
- 展示原理赔作业时间线及文件来源，供回溯使用。
- 材料可按类别和关联对象查看，并从字段或疑点定位到对应文件、页码或记录位置。
- 无法定位的字段须标明来源不足，不能生成虚构页码或引用。
- 结案状态与支付状态分别展示。不能把“已结案”推断成“已支付成功”。

### 6.3 启动审查与输入固定

- 启动前展示案件范围、适用保单和条款、已取得材料，以及人伤提示。
- 必须有可识别的审查对象。关键输入缺失且无法执行任何检查时，说明阻塞原因。
- 部分资料缺失时，对可执行项目继续审查，对受影响项目标明无法确认及所需资料。
- 重复点击同一次启动操作不能产生重复任务。
- 保存输入资料和适用条款版本。后续知识库更新不得改变历史审查依据。
- 相同资料重新审查须由人员显式发起，形成新任务并保留与原任务的关联。
- 人工补充证据可用于当前复核，单独记录补充时间和版本，不改写原 AI 审查输入。
- 如需 AI 依据补充资料重新分析，显式创建新任务；原任务和人工结论不得被静默覆盖。

### 6.4 审查节点与执行记录

页面展示以下业务节点及其实际结果：

| 节点               | 主要工作                                                   |
| ------------------ | ---------------------------------------------------------- |
| 档案整理与范围识别 | 建立事实、人员、车辆、损失和材料关系，识别人伤及范围外事项 |
| 保单与承保险种核验 | 对照保单、批单、保险期间和承保项目，确定检查范围           |
| 材料一致性核对     | 比较日期、车辆、人员、损失归属和重要字段，保留冲突原值     |
| 条款检索与依据核对 | 获取对应版本的条款，核对原处理意见是否有支持               |
| 金额与支付核对     | 检查可计算项目、重复记录线索和审批与支付的对应关系         |
| 发现与报告汇总     | 形成发现、证据链、未完成事项及待复核报告                   |

- 节点状态包括未开始、执行中、已完成、执行失败、无法执行和不适用，并展示耗时、摘要和原因。
- 每项实际检索和检查应与对应节点关联，不能用定时动画代替真实执行状态。
- 不适用或无法执行的检查，不算已通过。
- 范围内必要节点失败或无法执行时，任务可输出部分结果，但不能完成最终审查。
- 运行失败后保留已保存的发现和执行记录；重试或恢复应由人员显式发起，避免重复生成相同发现。

### 6.5 AI 与规则审查

#### 6.5.1 事实和材料核对

- 核对不同材料中的事故时间、车辆、人员、责任及损失信息。
- 区分字段缺失、格式错误和不同来源的值冲突。
- 记录每个值的来源，AI 不得自行选取某个冲突值作为已确认事实。
- 根据具体索赔项目及已取得资料判断证据是否足够；不能用一份统一材料清单直接判定所有案件缺件。
- 将“本次档案未取得”和“确认原作业未收集”分别表达。

#### 6.5.2 条款与处理依据核对

- 检索受具体保单、险种、产品和适用版本约束，不能混用其他案件的保单及错误版本条款。
- 识别并使用适用的特别约定和批单；影响无法判断时转人工确认。
- 规则检查、模型推断、原核赔意见和人工结论分开标注。
- 原审批通过只能作为待审查记录，不代表处理必然正确。
- 引用有效必须同时满足来源存在、属于本次范围、原文支持相应表述。仅引用编号合法不足以证明结论正确。
- 未找到足够条款依据时输出不确定性，不补造条款或肯定结论。

#### 6.5.3 金额与支付核对

- 分别处理申请、定损、理算、核赔和实付金额，保留各自口径。
- 对明确的加总、差额和重复记录检查使用确定性计算，保留公式、输入值及结果。
- 对复杂赔款计算，仅在适用规则、合同参数和必要事实齐备时复核；否则记录待核实事项。
- 核对同一损失项目是否存在重复计入线索；同时检查冲销、退款和付款失败等记录，不能仅按出现次数判定重复赔付。
- 核对核赔金额与有效支付记录的对应关系；保留分笔支付、不同收款对象及其授权信息。
- 金额差异须继续查找调整说明及证据，有合理说明时保留解释，不自动认定差错。
- 缺少价格或专业核损依据时，不能仅由模型认定维修价格过高或更换不合理。

### 6.6 疑点列表与证据查看

每条发现至少包含：编号、标题、所属检查、来源（规则/AI/人工）、涉及赔案和对象、关联保单及险种、发现说明、原始值、材料证据、适用条款或计算依据、不确定性、建议核实动作、人工处理状态。

- 首次生成的疑点统一为“待复核”，不等同于确认错误。
- 支持按状态、来源和涉及对象筛选，查看尚未处理事项。
- 列表中的数量和报告使用同一口径，不能将重复事件显示为多条疑点。
- 点击疑点进入详情，同屏查看问题、原始证据和人工复核表单。
- 条款或材料原文不足以支持模型表述时，审查人员能够排除疑点并留下原因。
- 人伤等范围外提示单独标明，不混入“车损问题已确认”的统计。

### 6.7 逐条人工复核

#### 6.7.1 处理动作

| 动作       | 业务含义                                 | 必须记录                             |
| ---------- | ---------------------------------------- | ------------------------------------ |
| 确认问题   | 经核实，确有差错、遗漏或处理缺陷         | 复核意见、事实和依据、建议后续动作   |
| 排除疑点   | 经核实，原处理有合理解释或 AI 发现不成立 | 排除原因及依据                       |
| 待补充核实 | 现有资料不足，尚不能确认或排除           | 缺少什么、待核实内容、跟进对象       |
| 转专业复核 | 需要专业人员进一步判断                   | 转交原因、接收人员或岗位、已提供材料 |

- 每次保存均记录操作人、时间、意见和补充依据。
- 确认、排除必须关联证据；仅填“同意”“无问题”不能作为完整复核结果。
- 复核意见可以关联已有材料、上传补充材料或带来源的业务记录。
- 待补充核实的事项收到资料后可以继续处理，保留历次记录。
- 转交不等于解决。须保存接收对象、跟进状态、专业意见和最终处理记录。
- 专业意见由授权人员录入并说明来源；首期不要求自动向外部人员发送消息。
- 复核意见变更须填写原因，保留前后版本及证据，不能覆盖历史。
- 重复提交不能产生重复决定；两人同时修改同一疑点时，后提交方须先查看最新结果再决定。
- 不提供未查看证据即对整案一键确认全部疑点的功能。

#### 6.7.2 人工补充发现

审查人员可新增 AI 未发现的问题，填写问题内容、涉及对象、原始证据和依据。人工新增项明确标记来源，并按相同规则保存复核结论及历史，不能冒充 AI 命中结果。

#### 6.7.3 后续建议与处理去向

确认问题后可填写建议补赔核查、支付纠正核查、补充记录或进一步调查等处理建议，并记录责任对象和去向。

“问题已确认”与“后续整改已办结”分开表示。车损审查完成不要求系统实际执行补赔，但报告须说明后续事项是否已办理。

### 6.8 审查报告

报告至少包括：

1. 审查编号、版本、生成时间和人员。
2. 目标赔案、关联事故、原结案和支付情况。
3. 本次范围、适用保单和险种、资料与条款版本。
4. 节点执行情况、已检查和未完成的项目。
5. 各条 AI、规则和人工发现及其原始证据。
6. 各条人工复核结论、人员、时间和意见。
7. 确认问题、排除疑点、待复核、待核实及转专业事项的分类汇总。
8. 人伤识别结果、范围外事项、数据缺失和其他判断限制。
9. 后续处理建议、去向及已知办理状态。

- AI 分析结束即可查看“待复核报告”；有未决事项时可保存阶段报告。
- 车损最终报告必须满足第 7 节的完成条件。
- 对车损范围内未发现疑点的情况，仍须人工查看检查覆盖情况并确认，填写意见后才能完成最终报告。
- 结论采用“在所列车损范围和资料内未发现疑点”“存在已确认问题”等准确表述，不使用超出范围的全案保证。
- 无法检查的关键事项必须展示，不能通过没有疑点来掩盖检查失败。
- 保存报告时固定其所引用的人工意见及材料版本。后续修订生成新版本，历史报告可查看且明确标记被后续版本替代。
- 资料不足、模型服务不可用或检索失败时，不能以模板报告冒充成功审查结果。

### 6.9 知识库和上传

提供可统一进入的资料管理功能，但按用途区分：

| 分类               | 管理要求                                                               |
| ------------------ | ---------------------------------------------------------------------- |
| 共享条款资料       | 保存来源、保险公司、产品、险种、真实版本及适用信息；供匹配案件检索     |
| 案件专属保单和批单 | 绑定案件及车辆，维护承保项目和特别约定，不能被其他无关案件作为保单使用 |
| 案件证据材料       | 绑定赔案、相关车辆或损失项目；保留文件和版本，供审查与人工复核使用     |

- 支持上传包含可提取文字的 PDF，明确展示文件格式、大小等上传限制。
- 支持为演示案件录入或导入结构化信息，并关联对应证据。人工录入须标明来源。
- 上传、解析、整理、可用和失败状态分别展示。上传成功不代表已经可用于检索或审查。
- 上传时填写文件类型、来源及归属，不能仅按文件名称猜测保单适用关系。
- 条款更新保存新版本；案件重新关联条款或保单须有明确操作和记录，不能自动替换历史任务依据。
- 扫描件、图片和无法解析文件应提示处理边界。首期不要求实现 OCR，也不得把无法读取的附件显示为已完成正文审查。
- 文件内容作为待核验资料，不得改变审查范围、工具权限和系统行为。
- 历史审查引用的文件版本应继续可追溯，不得因更新文件使原引用指向不同内容。

## 7. 状态与完成条件

### 7.1 三类状态分开管理

| 状态类别     | 示例                                     | 含义                                           |
| ------------ | ---------------------------------------- | ---------------------------------------------- |
| 原赔案状态   | 已赔付结案、拒赔结案、零赔付结案         | 原业务事实，审查不改变                         |
| 自动执行状态 | 未启动、执行中、已结束、失败、待恢复     | 表示程序执行进度，不代表人工复核完成或结论正确 |
| 人工审查状态 | 待人工复核、复核中、待核实、车损审查完成 | 表示本次车损审查的业务进度                     |

### 7.2 逐条状态

疑点初始为待复核。确认问题、排除疑点为人工结论；待补充核实、转专业复核为未决处理状态。所有后续变化保留操作历史。

### 7.3 车损最终审查完成条件

以下条件须同时满足：

1. 审查范围、输入资料和适用条款清楚且已固定。
2. 范围内必要检查已完成；不适用项具有理由，失败或无法检查项已补足条件并完成，或经人工明确调整审查范围且报告披露限制。
3. 范围内所有疑点已有确认问题或排除疑点的结论，不存在待复核、待补充核实或未完成专业复核的车损事项。
4. 审查人员已确认检查覆盖、报告内容及结论。

人伤属于范围外，可以仍处于专业复核中，同时完成车损报告，但须单独列明人伤转交和限制。若未决人伤相关事实会影响车损结论，则受影响的车损事项仍然未决，不能据此完成车损最终报告。

范围调整不能静默跳过失败检查，必须保留调整原因、人员、时间和对结论的影响。报告标题和结论须体现调整后的实际范围。

## 8. 认可的逐条复核操作示例

使用一份虚构已赔付结案赔案，AI 和规则提出三条待核实事项：

| 编号 | 发现                                                               | 初始状态 |
| ---- | ------------------------------------------------------------------ | -------- |
| F01  | 本次审批金额为 8,000 元，关联有效支付记录合计 9,000 元，需核实差额 | 待复核   |
| F02  | 初始申请金额为 9,000 元，核赔金额为 8,000 元，需核实调整依据       | 待复核   |
| F03  | 当前档案未取得第三方车辆损失的赔款计算书，无法复核相应金额         | 待复核   |

人工操作及结果：

1. 点开 F01，同屏查看核赔单、支付记录、金额口径及差额。人员核实不存在其他审批、退款、冲销或无效付款后，确认问题，记录建议交支付经办人员核查。系统只保存审查结论，不执行资金操作。
2. 点开 F02，查到签署的损失确认书及原核赔说明，确认最终认可金额为 8,000 元，选择排除疑点并关联材料。
3. 点开 F03，选择待补充核实，写明需调取计算书及跟进对象。取得材料后再继续处理，保留前次记录。
4. 报告显示确认问题 1 条、排除疑点 1 条、待补充核实 1 条，本次车损审查尚未完成，可查看阶段报告。
5. F03 最终核实后，满足完成条件才生成最终报告。若专业复核仍未结束，继续保留未决状态。

若 AI 未发现上述某问题，人员可手动新增并记录来源。若另发现人伤材料，单独显示人伤专业复核事项，车损检查继续。

## 9. 演示数据与验收样例

演示使用虚构资料，但须维护事故、赔案、保单、险种、损失、材料和支付之间的一致关系。异常样例须给出人工预先标注的预期结果，不能以模型自身输出作为正确答案。

至少准备以下样例：

| 样例                 | 预期验证                                                         |
| -------------------- | ---------------------------------------------------------------- |
| 正常结案案           | 资料和处理依据一致，系统不应编造问题；人工可确认范围内未发现疑点 |
| 认可的三疑点示例案   | 验证确认、排除、待核实三种处理及阶段报告                         |
| 人伤混合案           | 识别人伤并转专业，继续车损检查；报告不宣称完成全案审查           |
| 共用事实冲突案       | 人伤材料与车损资料在事故时间或责任上冲突，受影响项目保持未决     |
| 金额差异有解释案     | 有合理调整、分笔支付、冲销或退款，不能直接认定多赔或重复支付     |
| 条款或材料版本案     | 不同保单、版本及更新并存，历史任务始终引用正确版本               |
| 资料不足或服务失败案 | 清楚展示未执行和无法判断项目，不输出虚假的无问题结论             |

首期所有“结案审查完成”的演示案件，须具有可逐项核对的事实、适用条款、必要材料和预期人工结论。

## 10. 验收标准

| 编号 | 必须验证的结果                                                                                       |
| ---- | ---------------------------------------------------------------------------------------------------- |
| A01  | 可以查询已结案赔案，明确赔案范围、原结案状态及支付状态                                               |
| A02  | 一个案件能展示交强险、商业保单及其多个实际承保险种，损失归属清楚                                     |
| A03  | 本车和第三方车辆损失分别审查，保单、险种和证据不混用                                                 |
| A04  | 人伤线索及其来源可见；人伤、未知及冲突状态不会被当作无人伤                                           |
| A05  | 人伤转专业后车损继续；共用事实未决时，相应车损项目保持未决                                           |
| A06  | 审查节点来自实际执行记录，失败、无法执行、不适用与通过不混淆                                         |
| A07  | 每条疑点可定位原始记录、材料和适用条款，冲突原值均被保留                                             |
| A08  | 相同险种不同版本和其他案件保单不会被错误引用；更新不影响历史依据                                     |
| A09  | 金额差异、重复线索和无效付款等场景按记录关系核对，不能仅按数字不同判错                               |
| A10  | 人员能逐条确认、排除、待核实或转专业，必须保存意见和相应依据                                         |
| A11  | 人工补充发现来源清楚，复核记录的人员、时间及修订历史可追溯                                           |
| A12  | 重复提交不产生重复决定；并发修改不会静默覆盖他人结果                                                 |
| A13  | 待核实和未完成专业复核事项保留未决状态，转交不能自动变成已解决                                       |
| A14  | 有范围内未决事项时仅生成阶段报告；无疑点案件也须人工确认检查覆盖                                     |
| A15  | 车损最终报告满足完成条件，并明确人伤、资料不足及范围限制                                             |
| A16  | 报告区分 AI 发现与人工结论，数量正确，历史版本和引用可回溯                                           |
| A17  | 上传文件按条款、案件保单和案件材料区分归属；解析失败不会显示可用                                     |
| A18  | 补充证据、重新分析和报告修订保留版本关系，不改写原输入或原赔案                                       |
| A19  | 模型、检索或资料处理失败后明确提示并保留进度，不伪造成功报告                                         |
| A20  | 正常案、异常案、人伤混合案和资料不足案均完成实际输出与人工标注对照；记录遗漏、误报及证据是否支持结论 |

页面、规则和数据流程通过测试，只证明对应功能。真实模型与真实检索的发现质量、证据支持和人伤识别效果须以实际样例单独验证。没有实际结果时不得标记真实效果验收通过。
