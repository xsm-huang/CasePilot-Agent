# V1 接口、状态与事件契约（设计已批准）

本文件是已批准 [V1 设计](总体设计.md) 的目标契约。G2 知识库的导入、列表、进度与重试已实现，案件会话、新审核协议和 V1 SSE 仍为规划；当前分析接口继续使用 V0 格式，见 [功能流程](../使用/功能流程.md)。

可执行传输契约以 Python Pydantic 模型及其生成产物为准，不提前在前端维护另一套未接入的 DTO。实现差异和未验收项见 [实施状态](../开发/实施状态.md)。

## 1. 标识与共有约定

- `caseId`：案件；`conversationId`：案件内独立会话；`analysisId`：一次初始分析或追问。
- `messageId`：会话消息；`interruptKey`：本次待审核点，不能仅使用任务 ID 代替。
- `generationId`：不可变知识索引发布批次，与业务条款版本分开。
- `toolCallId`：一次工具调用；`sectionKey`：固定报告节键。
- 时间采用 ISO 8601；事件序号是每任务从 1 递增的安全整数。
- API 和事件边界进行运行时 Schema 校验，不依靠 TypeScript 类型断言代替校验。
- 创建任务、审核和恢复命令携带 `Idempotency-Key`。相同 Key/相同请求返回原响应；相同 Key/不同请求返回 409。Key 的作用域为操作类型与所属资源，校验幂等记录早于活动任务冲突判断。
- V1 保留 `/api/analyses` 资源名称，但请求需要会话上下文。当前只有项目内使用方，同步更新页面与脚本，不长期保留两套 V0/V1 执行逻辑。

## 2. HTTP 资源

| 方法与路径 | 输入/输出要点 | 语义 |
| --- | --- | --- |
| GET `/api/cases` | 案件摘要列表 | 仅查询；沿用演示案件 |
| GET `/api/cases/:id` | 结构化事实与材料来源、数据版本 | 不接受聊天直接修改 |
| POST `/api/cases/:id/conversations` | 可选标题；返回 conversationId | 201；固定所属案件，不跨案件复用 |
| GET `/api/conversations?caseId=...` | 会话摘要与活动任务 | 200；导航使用 |
| GET `/api/conversations/:id` | 消息、固定上下文版本、任务摘要、活动任务 | 200；历史消息分页，不能无限传入模型 |
| POST `/api/analyses` | conversationId、kind、question | 202；原子写入用户消息、任务和 start 命令 |
| GET `/api/analyses/:id` | 一致任务快照及 lastEventSeq | 200；刷新与切回时使用 |
| GET `/api/analyses/:id/events` | after 游标或 Last-Event-ID | SSE；只读取事件，不触发执行 |
| POST `/api/analyses/:id/review` | decision、comment、interruptKey、expectedRevision | 202；表示审核已持久接受，不等于报告完成 |
| POST `/api/analyses/:id/recover` | expectedRevision | 202；仅适用于可恢复任务，不覆盖旧审核决定 |
| POST `/api/knowledge/documents` | multipart PDF、productCode、clauseVersion、可选 expectedGenerationId | 202；返回 documentId/generationId；已有生效文档时必须提供预期 generation |
| GET `/api/knowledge/documents` | 险种、业务版本、文件与索引摘要 | 200；知识库页面使用 |
| GET `/api/knowledge/generations/:id` | 阶段、进度、错误、是否生效 | 200；导入进度采用短轮询，V1 不另建导入 SSE 协议 |
| POST `/api/knowledge/generations/:id/retry` | expectedRevision | 202；仅重试失败且未生效的导入，保留 attempt 记录 |
| GET `/api/analyses/:id/citations/:citationId` | 来源元数据、页码、原文、相邻块 | 200；仅允许定位该任务已关联的引用 |
| GET `/api/system/readiness` | 数据库、pgvector、模型配置/已验证能力状态 | 200；不返回 Key、完整连接串或触发付费探测 |

初始分析：`kind=initial`，question 可省略并使用明确的默认分析指令。追问：`kind=followup`，question 必填、去除首尾空白后 1～2000 字，且该会话已有完成回合。

创建任务前检查模型、固定 Embedding profile 和正确知识版本是否可用。预检失败不创建半条用户消息或孤立任务。通过事务和部分唯一约束保证同会话只有一个活动任务。

模型上下文建议为最近 6 个已完成回合、最近完成报告、当前问题和固定事实/依据；记录实际 messageIds。超过模型输入预算时明确处理，不截断核心规则或事实后继续冒充完整分析。

助手最终消息仅由服务器在报告定稿时写入并与任务关联；生成中展示任务章节，不重复插入“部分完成”的消息。失败回合在历史中可见，但不会作为已确认分析自动混入下一轮模型上下文。

## 3. 任务快照

建议最小响应结构（省略具体业务子结构）：

```ts
type AnalysisSnapshot = {
  id: string;
  caseId: string;
  conversationId: string;
  kind: 'initial' | 'followup';
  status: AnalysisStatus;
  caseSnapshot: CaseSnapshot;
  revision: number;
  lastEventSeq: number;
  userMessageId: string;
  assistantMessageId: string | null;
  context: {
    caseVersion: string;
    generationId: string;
    embeddingProfile: string;
    messageIds: string[];
    modelProfile: string;
    promptVersion: string;
  };
  facts: Fact[];
  ruleFindings: RuleFinding[];
  modelFindings: ModelFinding[];
  citations: Citation[];
  sections: ReportSection[];
  report: AnalysisReport | null;
  pendingReview: PendingReview | null;
  execution: {
    nodes: NodeExecution[];
    tools: ToolExecution[];
    timeline: TimelineItem[];
  };
  error: PublicError | null;
};
```

`revision` 用于业务更新冲突判断；`lastEventSeq` 用于流重放，二者不是同一概念。快照中状态、章节、审核点和游标必须来自一致数据库读取，不能独立拼接不同时刻的数据。

`caseSnapshot` 包含该任务使用的案件摘要、材料目录与来源字段，页面查看任务时据此渲染顶部金额、日期等信息，不以当前案件接口返回值覆盖旧版本。`execution` 包含到 lastEventSeq 为止的节点、工具和时间线投影；否则仅从 after 接流会丢失刷新前的执行记录。当前图有明确执行预算，投影规模有界，不必另建一套历史事件分页协议。

中间报告节失败时，可保留已提交 sections，但 report 和 assistantMessageId 保持 null；仅在全部节完成并定稿的同一事务中写最终报告、助手消息及完成事件。恢复复用已提交节，不清零模型/检索账本，也不重复发布业务章节事件。

关键证据结构：

| 结构 | 必填语义 |
| --- | --- |
| Fact | 稳定 factId、字段路径、值、来源类别、materialId（存在时） |
| RuleFinding | ruleCode、级别、说明、factRefs、发生冲突的 sourceValues |
| ModelFinding | 标题、推断、evidenceStatus、factRefs、citationRefs、待核查事项 |
| Citation | citationId、chunkId、generationId、documentId、文件名、险种、业务版本、真实页码、原文 |
| PendingReview | interruptKey、checkpointId、原因、关联发现、revision |
| ReportSection | sectionKey、该节内容、factRefs/citationRefs、committedAt |

检索距离可保留在服务端审计中，但不映射成模型推断的“置信度百分比”。报告页引用信息从 Citation 映射读取，不渲染模型自由填写的文件名或页码。

## 4. 状态机

| 状态 | 含义 | 合法后续 |
| --- | --- | --- |
| queued | 创建命令已接受，等待执行 | running、failed |
| running | 正在执行图节点 | waiting_review、completed、rejected、failed、recoverable |
| waiting_review | checkpoint 已确认暂停 | resuming；不接受同会话新问题 |
| resuming | 审核决定已持久接受，等待/正在恢复 | running、rejected、failed、recoverable |
| recoverable | 中断或对账后需要明确恢复处理 | queued；同会话仍视为活动任务 |
| completed | 全部报告章节验证并定稿 | 终态，只读 |
| rejected | 当前审核决定结束任务 | 终态，不生成报告 |
| failed | 任务不能按当前流程继续 | 终态，不伪装为完成 |

人工审核需要等待审核状态与 interruptKey 都匹配。审核通过不删除事实与疑点；驳回不是“重新分析”。恢复操作从已确认 checkpoint 继续，不从浏览器拼装图状态。

终态任务的新分析必须创建新 analysisId。证据不足是报告的业务属性，不等同于执行失败；未能验证输出结构或引用则不得进入 completed。

知识索引状态独立为 `queued → parsing → chunking → embedding → ready / failed`；ready 不自动表示当前生效，还必须匹配 publication 指针。旧 generation 仍可供已固定上下文的会话与历史报告使用。

单进程重启发现上次执行中的未发布 generation 时，标记 failed，错误码 INDEXING_INTERRUPTED，旧发布指针不变；retry 为该 generation 创建新的处理 attempt，只重建未发布产物。尚未开始的 queued 导入可继续，不把中断任务永久留在 embedding 状态。

## 5. SSE 协议

沿用 HTTP SSE，统一 `event: timeline`，`id` 为当前任务的 seq。以下 payload 为拟定外层：

```ts
type EventEnvelope<T> = {
  schemaVersion: 1;
  analysisId: string;
  conversationId: string;
  seq: number;
  at: string;
  type: string; // 实现为判别联合，不保留任意字符串 payload。
  data: T;
};
```

| type | 核心 payload | 页面处理 |
| --- | --- | --- |
| analysis.status | status、revision | 更新权威业务状态 |
| node.started / node.completed / node.failed | nodeExecutionId、nodeKey、attempt、摘要、耗时 | 更新同一节点记录 |
| tool.started / tool.completed / tool.failed | toolCallId、toolName、attempt、摘要、耗时 | 更新同一工具卡片，不靠名称配对 |
| analysis.ready | 规则、模型发现、证据充分性、引用映射 | 展示可核查的分析结果，不标最终报告 |
| review.required | interruptKey、checkpointId、revision、审核原因 | 展示本次审核表单 |
| review.accepted | interruptKey、decision、revision | 清除待提交状态，等待执行结果 |
| report.section | sectionKey、内容、引用映射 | 按键替换/补齐章节，保持生成中 |
| report.completed | 完整报告、assistantMessageId、revision | 以最终结果对账并标记完成 |
| analysis.rejected | 审核意见、revision | 展示驳回并关闭流 |
| analysis.failed / analysis.recoverable | 稳定错误码、消息、可否恢复、revision | 清晰展示失败或恢复入口 |

节点内部重试会产生明确 attempt；业务工具重放复用已提交结果时不伪造新的完成卡片。报告 sectionKey 固定为 `summary`、`findings`、`recommendations`，顺序生成，已提交的节不因重连重复追加。

正式事件、快照投影和相关状态在同一业务事务中写入。分配 seq 时锁定任务行，不裸用 `MAX(seq)+1`。SSE 从同一事件表按 seq 顺序批量读取；无数据时等待短轮询，并发送不占业务序号的 SSE 注释心跳。

### 游标与隔离规则

1. 首次进入/切回：读取快照，然后订阅 `events?after=lastEventSeq`。
2. 同一 EventSource 自动重连：使用 `Last-Event-ID`。有该 Header 时优先于 URL 的初始 after；无 Header 才读取 after。
3. 游标非整数、负数或超出安全范围返回 400；大于已提交最大 seq 返回 409，客户端改为重新取快照。
4. 传递语义为至少一次。前端按 `(analysisId, seq)` 去重；发现不连续序号先重新同步，不猜测遗漏内容。
5. 先补发终态任务的剩余事件，再结束连接。前端确认终态后主动关闭，不无限重连。
6. 切换会话会关闭旧连接，不取消后端执行。旧 HTTP、SSE、catch/finally 回调不得更新当前选择的内容或连接状态。

## 6. 审核命令与错误

审核示例：

```json
{
  "decision": "approve",
  "comment": "继续分析，保留事故日期疑点。",
  "interruptKey": "当前快照提供的中断标识",
  "expectedRevision": 7
}
```

decision 仅允许 approve/reject；comment 最长 2000 字。相同幂等键重试返回已接受结果，不再次恢复；新键重复或决定相反、版本过期均返回冲突。前端 409 后重新读取快照，不自行假定提交成功或失败。

| HTTP / code | 用途 |
| --- | --- |
| 400 / INVALID_INPUT | 请求格式、问题内容、游标不合法 |
| 404 / NOT_FOUND | 案件、会话、任务、引用不存在或不属于该资源 |
| 409 / ACTIVE_ANALYSIS_EXISTS | 同会话已有活动任务 |
| 409 / REVIEW_CONFLICT | 中断点、审核版本或决定冲突 |
| 409 / IDEMPOTENCY_CONFLICT | 同 Key 对应了不同请求 |
| 409 / GENERATION_CONFLICT | 知识库发布预期版本已变化 |
| 409 / EMBEDDING_PROFILE_MISMATCH | 查询与索引模型或维度配置不一致 |
| 413 / DOCUMENT_TOO_LARGE | 文件或页数超限 |
| 415 / UNSUPPORTED_DOCUMENT | 非批准格式或不支持的文档类型 |
| 422 / KNOWLEDGE_NOT_READY | 没有正确业务版本的生效索引 |
| 422 / DOCUMENT_PARSE_FAILED | 文件为空、损坏、加密或没有可用文字 |
| 503 / DEPENDENCY_UNAVAILABLE | 数据库、模型或 Embedding 依赖不可用 |

运行中发生 OUTPUT_VALIDATION_FAILED、MODEL_TIMEOUT、MODEL_BUDGET_EXHAUSTED、RECOVERY_CONFLICT 等错误时，写入任务错误字段并发出对应失败/可恢复事件。错误响应使用稳定 code、可读 message、requestId；不包含 Key、内部堆栈或完整提示词。

## 7. 接口实现前共同确认

确认以上标识、状态机、游标、审核幂等、报告节及引用类型后，后端提交共享 Schema，前端与测试共同评审。新增接口只在需要时加入；不为了兼容尚不存在的消费者增加通用协议层。
