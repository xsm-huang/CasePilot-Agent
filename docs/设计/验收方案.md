# V1 测试与验收方案

本文件随 [V1 设计](总体设计.md)、[契约](接口与事件契约.md) 获准实施。下列内容是完整 V1 的通过标准；部分确定性与数据库项已有覆盖，具体结果见 [实施状态](../开发/实施状态.md) 和 [测试说明](../开发/测试说明.md)。

## 1. 三层证据，分别报告

| 层次 | 使用环境 | 能证明什么 | 不能替代什么 |
| --- | --- | --- | --- |
| 确定性测试 | stub 模型/Embedding、固定事件与响应 | 规则、路由、Schema、预算、引用边界、页面归并 | 真实模型调用和检索质量 |
| 数据库/进程集成 | 实际 PostgreSQL/pgvector、迁移、Repository、checkpointer；部分模型可 stub | 数据约束、事务、发布、重启恢复、事件一致性 | 实际 Embedding 与模型的语义行为 |
| 真实联合验收 | 批准的模型/Embedding、实际数据库、实际浏览器 | 简历能力的真实闭环与结果质量 | 不得以配置存在或 stub 成功代替 |

测试结果明确标为通过、失败、阻塞或未执行。缺少 Key、数据库、样本或预算时记阻塞，不能跳过后汇报全部通过。只用虚构案件及自编演示条款；测试数据库与开发数据库分开，清理操作限定测试 schema 和已知夹具。

## 2. 验收矩阵

| ID | 对应能力 | 层次与步骤 | 通过标准 |
| --- | --- | --- | --- |
| T01 | 模型与 Embedding 前提 | 真实服务：核对所选配置，执行最小工具调用、结构化响应和 Embedding | 记录实际 provider/model/维度及请求结果；不支持能力则阻塞，不静默换模型 |
| T02 | 真实 Tools | 单元+图+真实模型：查询、校验、初检、模型触发补检；输入非法工具参数 | 工具具有 Schema，实际调用服务；案件/版本不可由模型改写；补检有真实 toolCall 记录 |
| T03 | 缺件与跨来源规则 | 单元：齐全、缺发票、重复类型、日期缺失/无效、材料间及材料与案件日期不同 | 稳定规则编码；缺失/无效/冲突可区分；冲突列出真实来源和值；模型不覆盖事实 |
| T04 | PDF 解析与分块 | 集成：多页、多条号、跨页条款、空白、扫描、加密、损坏及超限 PDF | 支持的文件保留真实页码和正文；不支持文件失败且不可检索，不伪造页码或 OCR 成功 |
| T05 | 实际向量索引 | 实际 Embedding→实际 vector(D) 写入→真实查询；故意改变维度/profile | 正常链路可复现，向量不是固定假数据；不匹配明确失败，不自动混库 |
| T06 | 版本与险种隔离 | 数据库：同名条款放入不同险种/版本，错误版本故意更相似 | 每次返回的错险种、错版本、错 generation 数量为 0；正确版本缺失时不回退 |
| T07 | 原子发布 | 故障注入：第 N 批 Embedding 失败；索引构建中查询；并发发布；重复导入；embedding 阶段强停重启 | 仅完整旧版或完整新版可见；失败/中断不改变生效指针；中断导入变 failed 并可显式 retry；不更改已发布块、不永久卡中间态 |
| T08 | 来源快照 | 分析后上传同版本新 PDF，再恢复原任务、追问及查看历史 | 原会话固定原 generation，新会话可选择新 generation；旧引用仍定位原页码/正文 |
| T09 | 语义召回 | 固定题集：用不依赖相同词面的人工改写问题检索 | 建议有答案题 Hit@4 ≥ 90%；元数据隔离 100%；保存题集、配置及返回片段，不只判断“有结果” |
| T10 | 无相关依据 | 真实检索+模型：只有近似但不支持的文本、库外问题 | 明确证据不足及待补充项；不把最近邻自动当依据；不编造条款或确定性责任结论 |
| T11 | 动态分支与预算 | 图 stub 强制持续请求补检；真实模型样本覆盖补检和不补检；审核/重启/恢复及剩余额度不足 | 首检 1 次、补检最多 2 次；重复/无新增依据提前结束；模型调用含修复最多 8 次，调用前预占、重启不清零；分析预留报告额度，不足则明确预算失败 |
| T12 | 结构化与引用白名单 | 单元+模型：错误 JSON、缺字段、未知事实/块 ID、其他任务 ID、旧版 ID | 最多一次结构修复且计入全局预算；无效结果不标完成；服务端回填文档与页码 |
| T13 | 引用支持结论 | 人工标注真实输出：真实但不相关片段、遗漏否定或限制条件 | 关键结论由相应片段实际支持；受审样本的关键无依据结论数为 0；ID 合法不算此项通过 |
| T14 | 真实分节增量 | API+浏览器：第一节完成时延迟第二/三节调用；中间一节报错 | 第一节在后续节未完成时已可见；能关联三次实际生成；不采用完整结果拆字或定时播放；失败时 report/assistantMessageId 为 null，不标定稿 |
| T15 | 工具与时间线 | 前端组件：同名多次调用、开始/成功/失败/重试、重复事件 | 按 toolCallId/nodeExecutionId 配对；状态和耗时与实际记录一致；无重复完成卡片 |
| T16 | 快照与 SSE 一致性 | API：读快照后产生事件、读取期间产生新事件、自动重连与主动重建连接 | after 与 Last-Event-ID 规则正确；已提交事件无缺口；重复去重；正文节不重复追加 |
| T17 | 游标及终态 | API：非法、过大游标；终态补发；无数据心跳 | 400/409 语义符合契约；心跳不占业务序号；终态补发完可关闭，无无意义重连 |
| T18 | 多会话隔离 | 组件+浏览器：同案两会话、不同案件；A→B 快切并延迟 A 请求/流/错误/finally | B 中 A 的消息、章节、错误、审核意见、工具状态数量为 0；切回 A 可恢复权威状态 |
| T19 | 多轮上下文 | API+真实模型：初次分析后两轮追问，其中一次需补检；另开独立会话 | 追问使用本会话上下文，创建新 analysisId；历史报告不覆盖；其他会话上下文不混入 |
| T20 | 会话串行约束 | 数据库并发：同会话同时创建两个任务；待审核时追问；不同会话执行 | 同会话最多一个活动任务；冲突 409；等待审核不触发新模型调用，不妨碍其他会话查看 |
| T21 | 人工审核 | 图+浏览器：有疑点暂停、通过、驳回、无疑点直达 | 待审无最终报告；同任务恢复；规则疑点保留；驳回无报告 |
| T22 | 真正的进程恢复 | 独立进程：待审核后终止 API，新进程使用同数据库再提交审核 | 原 analysisId/中断点/疑点/事件存在，从原位置继续；仅刷新页面不算通过 |
| T23 | 审核幂等与并发 | HTTP+数据库：相同 Key 重试、同 Key 不同内容、不同 Key 的通过/驳回并发、过期 interruptKey | 同中断只接受一决定；相同请求返回原结果；冲突 409；只产生一个有效恢复和最终报告 |
| T24 | 崩溃窗口 | 故障注入：审核入库后未恢复、checkpoint 推进后未投影、章节入库后未推送、模型返回后未落库 | 待执行命令可对账；已提交节不再生成/提交/发业务事件；模糊调用仍占预算，恢复不清零；事件可补发；外部调用可能重复的边界如实记录 |
| T25 | 历史与溯源 | 浏览器：重启后查看消息/报告/审核，点击引用；故意请求不属于任务的引用 | 数据来自数据库；实际文档位置可定位；越界引用拒绝；localStorage 不充当实体存储 |
| T26 | 明确失败与输入边界 | 配置缺失、数据库离线、模型超时、Embedding 失败、文档提示注入、HTML 输出 | 展示稳定错误，不回退模板/关键词库冒充真实；文件文本不改变工具边界；HTML 不执行 |

## 3. 评测数据与目标

保留两件 V0 案例，增加至少：跨材料日期冲突、非法/缺失日期、无对应业务版本、没有相关依据、补检后仍不足、同案独立会话。数据标注包含事实来源、预期规则、允许引用及必须保留的不确定性。

检索集建议至少 24 题：12 题有依据的语义改写/跨段问题、6 题险种/版本干扰、6 题无相关依据。为有答案题标注相关 chunk/条款集合；无答案题不进入 Hit@4 分母，单独检查错误引用。分块调整后同步更新 chunk 映射，但不改变标注依据来迎合检索结果。

报告集建议至少 10 个案件/问题样本，每个样本真实运行 3 次，检查规则稳定性、引用范围和语义支持。实际请求数量会包含工具决策、分析修复和三节生成，不能简单按“30 个任务”估算成本；执行前按批准预算核对并设置停止上限。

Hit@4 ≥ 90%、样本数及重复次数是本草案的验收目标，不是既有成绩，也不是普适质量保证。先冻结数据与参数，再评测；不能把测试答案塞进业务提示词或为个别演示题硬编码检索路径。

真实验收记录至少保存：时间、提交/文件版本、运行命令、依赖与模型配置摘要、提示词与分块版本、generation、样本 ID、返回引用、token 用量/可得成本、实际耗时及错误。密钥和完整连接串不得出现在记录中。

## 4. 可读性与维护性门槛

1. `App.vue` 只组合页面；组件不直接请求数据库相关接口或自行推导业务状态；API、流连接、事件归并与展示职责清楚。
2. 图定义只表达编排。规则、提示词、SQL、工具实现及引用检查不能继续堆在工作流构造函数中。
3. 类型边界共享，SSE 为判别联合；不以 `any`、连串类型断言和复制 DTO 掩盖接口差异。
4. 状态转换、检索预算、配置与错误码有单一来源；不存在跨层互相偷偷覆盖状态的写法。
5. 数据库约束与事务语义有对应测试；Promise、后台命令和恢复错误都有明确处理，无空 catch 或悬空任务。
6. 一个模块的职责应能从命名和依赖看懂。若理解核心路径需要多处隐含约定或大量口头说明，先整理代码再验收。
7. 不强制机械的文件行数或覆盖率指标；以职责、重复、嵌套、可独立测试和实际评审为依据，避免为“拆文件”产生无用抽象。

前端、后端和测试均参与最终可读性审查。测试发现问题时记录输入、实际表现、期望、影响与复现步骤，而非仅附截图或“有问题”的描述。

## 5. 实施期间暂停与沟通

当前模型、文字 PDF 范围和 PostgreSQL 方案已确定；涉及新增范围或批量真实服务验收时，按实际调用量核对预算和停止上限。

若模型能力、数据库环境、真实质量或崩溃一致性无法满足方案，暂停相关链路并提交证据与选项。跨会话污染、错版本引用、无依据关键结论、重复审核恢复为阻断问题，不能用页面隐藏、禁用测试或改回模拟结果结束验收。

日常可在既定设计内修复普通缺陷；涉及范围变化、新增基础设施、替换模型或放宽质量目标时，必须先与用户沟通。用户要求暂停的开发，在获得继续指示前不恢复。

## 6. V1 完成定义

- 设计和契约经过审阅，实施变更有记录。
- 类型检查、构建、相关确定性测试和数据库/进程测试通过。
- 真实 Embedding、pgvector、模型工具调用、动态补检与引用验收通过。
- 真实分节增量、多轮会话、流重连、并发审核和停进程恢复通过。
- 无阻断缺陷，三角色可读性评审通过。
- 文档和简历能力对照表按实际能力更新；未完成项明确保留，不以“已配置”冒充“已验证”。

只有满足这些条件，才能将已批准范围的 V1 标为完成。已有测试覆盖不等于完整条目通过，当前 G0 真实模型、G3/G4 业务和 G5 联合验收仍未完成。
